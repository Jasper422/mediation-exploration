# 确认与分析状态

## 两个确认点

每个节点先给出具体可审查的方案，再问是否正确。不要只问“可以继续吗”，也不要在没有读取文件时把识别变量的工作交回操作者。第三、第四步分别确认，不能把两次确认合并成一个默认通过的问句。

### 第三步确认内容

先展示“计分与测量理解 v1”，至少包括：

| 项目 | 已读取的证据及当前理解 | 待确认处 |
| --- | --- | --- |
| 处理/分组 | 来源工作表、字段、类别标签、参照组和对比方向 | 编码是否对应研究设计 |
| 每个中介 | 构念名称、每个题项的来源列/题干、分值范围、题意方向 | 归属和反向题是否正确 |
| 合成规则 | 反向公式、均值/总分、最低有效题数及缺失规则 | 操作化是否正确 |
| 每个 DV | 来源字段、单位、量尺类型、越高代表什么、总额限制 | DV解释和单位是否正确 |
| 设计 | 个体/重复/聚类单位、施测顺序与可能的处理后变量 | 未从文件确认的部分明确标记 |
| 文本 | 自由回答来源与题目要求 | 是否有独立人工编码或编码手册 |

随后向操作者提问，例如：

> 请确认以上“计分与测量理解 v1”是否正确，尤其是题项归属、反向计分、得分合成和 DV 含义。未知项已在表中标明，未据此擅自计分。
>
> 1. 是
> 2. 否，并补充
> 3. 部分同意，并补充

交互工具的三个 options 必须逐项保持上述原文。选择“2”或“3”时，界面允许自由补充；若未补充关键更正，继续追问需要更正的项目，不能把它解释为批准。

第三步通过后才形成正式分析得分并做信度/构念区分检查。确认不是证明量表有效；诊断结果及其局限还需在第四步方案中说明。

### 第四步确认内容

计分已确认、初步测量检查完成后，展示“候选与分析方案 v1”：

1. 每个 DV 的单中介名单、双中介并行名单、理论/设计纳入理由、明确排除的结构；给出模型数和特定路径数。
2. 每个结构的方程或示意，X 的对比、拟估计的量，以及是否存在时序与因果方面的限制。
3. 主分析样本规则、缺失处理、协变量及其处理前/处理后身份；不把所有可见字段一律控制。
4. 与结果类型和采样单位匹配的估计方法、bootstrap/其他区间方法、独立单位、重复次数和种子方案。
5. 多重比较的检验族及校正方式，哪些区间只是逐项区间；两类报告如何呈现优先级。
6. 计划中的敏感性规格及其理由；哪些会改变计分、样本或估计目标。

随后提问：

> 请确认以上“候选与分析方案 v1”是否符合研究问题，包括单中介/双中介范围、纳入理由、控制变量、比较规则和稳健性方案。确认后我再批量拟合模型。
>
> 1. 是
> 2. 否，并补充
> 3. 部分同意，并补充

不要求操作者具备统计编程知识。对检验族、bootstrap 和并行/链式的必要说明用短句解释；模型很多时给出一张精简确认表及完整候选清单的可访问位置。

## 暂停和恢复

在分析目录保存 `decisions.md` 或同等记录：数据版本/指纹、确认节点、方案版本、当次展示内容、操作者实际答复、补充更正、确认范围、仍未知事项和接下来可做的工作。保存引用或摘要，不伪造用户原话。

状态迁移：

| 当前状态 | 答复/变化 | 下一状态与允许工作 |
| --- | --- | --- |
| 第三步待确认 | 是，无实质更改 | 第三步通过；计算得分和测量诊断，准备第四步 |
| 第三步待确认 | 否/部分同意 | 修订第三步，展示修订版，等待确认 |
| 第四步待确认 | 是，无实质更改 | 第四步通过；按已确认范围拟合模型 |
| 第四步待确认 | 否/部分同意 | 修订第四步，展示修订版，等待确认 |
| 任一待确认 | 超时、无答复、无关输入 | 保持待确认；只做不依赖该答复的工作 |
| 已通过 | 来源文件、题项归属或计分有实质更改 | 第三步及其下游方案失效；重新确认变化后的理解 |
| 已通过第四步 | 新增结构、控制变量、主样本规则或检验范围 | 第四步实质修订需要确认；原结果保留并标记版本 |

常规重跑、图表配色、文字排版或已确认规格中的诊断执行不触发额外确认。对话中已有相同版本的明确授权可以沿用；只读取磁盘“approved=true”不能自行判定审批通过。

当操作者只是要求设计/创建这个技能时，这两个节点是技能未来执行数据分析时的交互规则，不要在技能创建过程中错误要求操作者确认旧数据映射。
